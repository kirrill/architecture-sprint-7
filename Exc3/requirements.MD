# Список требований

## Требования к безопасности
* Управление доступом:
    * Обязательная двухфакторная аутентификация при входе в пользовательское мобильное приложение
    * Доступ к smart-home-api должен осуществляться только для авторизованных пользователей, и с ограниченного списка адресов
* Безопасность данных
    * Шифрование трафика между компонентам системы
    * Шифрование данных на уровне БД (как минимум для БД биометрии и персональных данных пользователей)
    * Регулурное резервное копирование БД
* Защита инфраструктуры
    * Доступ к smart-home-api должен осущесвляться через межсетевой экран для белого списка адесов 
    * Обязательное наличие антивирусных программ на серверах и регулярное обновление их баз
* Управление инцидентами
    * Настроить SIEM-систему для выявления аномалий и попыток несанкционированного доступа

## Протоколы аутентификации и авторизации
Аутентификация пользователя (собственника) в мобильное приложение должно быть, как минимум, двухфактороной. Например логин/пароль + одноразовый пароль.
Авторизация пользователя должна осущесвляться на базе его атрибутов (ABAC). Пользователь может видеть/редактировать только свои данные, помещения,устройства и т.д.

Аутентификация и авторизация в биометрическом API должна осуществляться с использованием протокола OAuth 2.0

## Взаимодействие между системами предприятия и внешней платформой
Взаимедействие между системой "Группой сервисов ЖКУ" и "Провайдером услуг умного дома" осуществляется в обе стороны.
Провайдер услуг умного дома предоставляет свой API для взаимодействия с домофоном и шлагбаумом. Посредством этого API собственник может просмотреть видео с домофона/камеры шлагбаума, отправить команду открытия, принять звонок с домофона.

В свою очередь "Группа сервисов ЖКУ" также предоставляет свой API (smart-home-api), посредство которого Домофоны могут отправлять "фото" со своих камер для сличения с БД биметрии собственников. Шлагбаумы могут отправлять уже распозннаный номер авто в текстовом формате, для поиска в БД собственников.
